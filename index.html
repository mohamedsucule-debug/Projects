Design Engineering Lab no frameworks · no build step · no dependencies

Interfaces for systems that refuse to be simple.

Six working tools. Each one starts with the hard part — a regex compiler, a cost-based query optimiser, the Raft protocol, a critical-path analyser, Myers diff, OKLab colour maths — implemented from scratch, and then asks the actual design question: what does a person need to see to understand this?

They are not mockups. Every number on screen is computed live by the engine beside it, every algorithm is the real one, and the parts that are approximations say so out loud.

How this is built

Engine and interface are separate. Every project is a pure engine.js — no DOM, deterministic, unit-tested — plus an index.html that renders it. The engines are the part that must be correct; the interfaces are the part that must be understood.

One design system. shared/lab.css holds every token: one accent, hairline structure, monospace for anything a machine produced and sans for anything a human reads. Both themes are first-class.

No framework, on purpose. The whole shared runtime is 60 lines: an element factory, a fixed-step ticker, a HiDPI canvas helper, a seeded PRNG. These are interfaces about data, not about state management.

Honest about limits. Each project's README ends with what it does not do. A demo that hides its edges teaches the wrong lesson about the system it is modelling.

Run it. Clone, then npx http-server (or any static server) and open the root. ES modules need a server; nothing else does.

Test it. node tests/run.mjs — no test framework, no install. The suite checks the properties that make each engine correct, not the pixels.

Built with Claude Code. Every engine here is reimplemented from the papers and specs, not wrapped around a library.

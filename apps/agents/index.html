Agents the loop is easy, the failure modes are not

The loop is ten lines. Everything hard is elsewhere.

Send the conversation; get back an answer or a request to call a tool; call it; append the result; send it again. Everybody writes that correctly the first time.

Then a tool throws. Then one returns five kilobytes. Then the model asks for a tool that does not exist, or passes a number where a string goes, or calls the same thing four times in a row. None of that is in the loop, and all of it is what running one of these actually is. Below you can break it on purpose and switch the guards off one at a time.

One · Step through it

A real task over a real ledger: 300 expense lines and five tools that genuinely run over them. Pick something to go wrong, then step through and watch the message blocks accumulate. The tool results really are computed, and the answer at the end really is the number in the data.

Two · Switch the guards off

Each of these exists because of one specific way a run goes wrong. Turn one off, re-run the matching fault, and watch what it was preventing. A harness is defined by what it survives, not by how neatly the happy path reads.

Three · Every turn pays for every turn before it

The conversation is stateless on the wire. Turn four resends turns one, two and three — plus every tool definition, every time. So the cost of an agent is not the number of turns, it is roughly the square of it, and a chatty tool is expensive twice: once when its output arrives, and again on every subsequent turn forever.

Four · What is real here and what is not

the modela script
There is no API key on this page and it is not going to ask you for one. The policy emits the same blocks a model would, on a schedule.
Why a script is the right call here, not a compromise. You cannot reliably get a real model to pass an argument of the wrong type, or to call the same tool four times in a row, at the moment you want to show what your harness does about it. Here it is a dropdown. And the interface between the two is one function — policy({ messages, tools, turn }) → { content }, the shape of a single completion — so a real model drops in behind it without the harness knowing. That boundary is the thing worth designing, and it is why it is a plain function rather than anything clever.
The harness is harness.js, the tools are tools.js, the scripted policy is policy.js. 29 tests, including one that every tool result is tied to the call it answers, and one that the agent's arithmetic matches the ledger. Nothing is sent anywhere. Full write-up.
